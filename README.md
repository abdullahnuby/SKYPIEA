# SKYPIEA + Beno — الشركة أولًا، والمساعد ضمن الخدمات

**الإصدار:** `1.0.0-alpha.13` — تحسين الويجت ورسالة ترحيب تلقائية تعرّف الزائر بـBeno، مع الحفاظ على صفحة SKYPIEA كشركة وخدماتها.

صفحة SKYPIEA العامة تعرّف بالشركة وخدماتها الهندسية والتكنولوجية، وتعرض قطاعاتها ومنهجية العمل والنبذة عن الشركة ونموذج التواصل. يظهر **Beno** في قسم منتج مميز ضمن الحلول التكنولوجية، وتوجد دعوة لاستخدامه داخل القسم وبطاقة خدمات التكنولوجيا، بينما تبقى بقية خدمات الشركة ظاهرة ومستقلة.

## التجربة العامة

- تعريف SKYPIEA أولًا: الرسومات الهندسية والإشراف والتنفيذ، والمواقع وتطبيقات الويب، وأنظمة الأعمال، والذكاء الاصطناعي والأتمتة.
- قسم **قطاعاتنا** يقدّم الهندسة والتكنولوجيا كلًّا على حدة.
- قسم **خدماتنا** يعرض خدمات القطاع المحدد عبر تبويب تفاعلي؛ يظهر Beno كخدمة متخصصة ضمن قطاع التكنولوجيا.
- قسم مميز لـ **Beno** يشرح دوره ومنافعه، مع معاينة توضيحية مميزة وزر لفتح نفس تجربة المساعد. لا تستبدل المعاينة أسعارًا أو كميات فعلية.
- تبقى أقسام قيمة الشركة ومنهجية العمل و«عن SKYPIEA» والتواصل عبر WhatsApp ونموذج طلب الخدمة موجودة.
- تظهر رسالة ترحيب صغيرة من الويجت بعد نحو ثانيتين في أول جلسة التصفح، مع خيار تجربة Beno أو إخفاء الرسالة. يظل الشات الكامل مغلقًا حتى يختاره الزائر، ولا توجد رحلة تسجيل أو فلو إجباري.
- تعمل الصفحة باللغتين العربية والإنجليزية وبالتصميم المتجاوب؛ اختبارات Alpha 13 تتحقق من بقاء أقسام الشركة، وظهور الترحيب، وفتح المحادثة عند اختيار الزائر فقط.


## تشغيل محلي

يتطلب Node.js 20 أو أحدث، وPython مع Playwright/Chromium فقط لاختبار المتصفح.

```bash
npm run build
npm test
npm run check:secrets
npm run audit:knowledge
npm start
```

ثم افتح `http://127.0.0.1:4173`. وضع التشغيل المحلي يفعّل `BENO_LOCAL_DEMO=1` لحفظ leads في ذاكرة العملية فقط؛ لا يُستخدم هذا الوضع في الإنتاج.

اختبار المتصفح الاختياري:

```bash
npm run test:browser
```

## التوثيق الفني

- `docs/ENGINEERING-AUDIT-2026-10.md` — تدقيق الوضع الفعلي، ما يعمل وما هو ناقص، وأولويات المخاطر.
- `docs/ROADMAP.md` — خطة الدفعات التالية مرتبة بحسب القيمة والاعتماديات.
- `docs/SKILLS-INVENTORY.md` — جرد المهارات المنفّذة والجزئية والمخططة مع أدلة الاختبار.
- `docs/BOQ-ORGANIZATION.md` — هيكل مراحل التنفيذ ومجموعات العمل وأنواع البنود، وحدود الكميات التقديرية.
- `api/_data/boq-knowledge.v1.json` — مصدر قواعد نطاق الشمول، فصل التوريد عن المصنعية، إدارة الهالك، المرادفات والتصنيف الموحد.
- `AGENT-DATA-QUALITY-REPORT.json` — تقرير جودة بيانات الوكيل والتكرارات والوحدات والفجوات.
- `PRICE-BOOK-QUALITY-REPORT.json` — جودة كتالوج الأسعار؛ لا تعني التغطية الرقمية اعتماد السعر للتنفيذ.

## نشر واحد على Vercel

1. ارفع **محتويات هذا المجلد** إلى ريبو SKYPIEA نفسه؛ `index.html` و`package.json` و`vercel.json` يجب أن يكونوا في جذر الريبو.
2. استورد هذا الريبو إلى مشروع Vercel الحالي. استخدم Build Command: `npm run build` وOutput Directory: `dist`.
3. تضبط إعدادات السيرفر في Vercel Environment Variables، ولا تُكتب داخل HTML أو ملفات `dist`:
   - `BENO_MARGIN_PCT` — نسبة الهامش داخل الخادم فقط.
   - `BENO_MARGIN_MODE` — مثل `comprehensive` أو `supervision`.
   - `BENO_MIN_COVERAGE` — الافتراضي `0.70`.
   - `ALLOWED_ORIGINS` — نطاق SKYPIEA الإنتاجي، مع `www` إن استُخدم.
   - `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` — أسرار خادم فقط.
   - `BENO_DURABLE_RATE_LIMIT=1` عند تجهيز RPC الخاصة بتحديد المعدل في Supabase.
   - `BENO_ADMIN_PASSWORD` كلمة مرور المدير (12 حرفًا على الأقل) و`BENO_ADMIN_SESSION_SECRET` سر جلسة عشوائي (32 حرفًا على الأقل). لا تعِد استخدام كلمة مرور التطوير.
   - `OWNER_WEBHOOK_URL` اختياري.
4. طبّق `supabase/migrations/20261021_admin_price-control.sql` على قاعدة Beno الحالية. إذا كانت القاعدة ما زالت تستخدم أسماء MIYAR القديمة، طبّق `supabase/migrations/20261021_rebrand_rate_limit.sql` أولًا. لقاعدة جديدة استخدم `supabase/schema.sql`. هذا يضيف تخزين المسودات والإصدارات ووظيفة النشر الذرّية ويحدّث نطاق تسجيل محاولات الدخول.
5. لا تضبط `BENO_LOCAL_DEMO=1` في الإنتاج. يلزم وجود `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` لأن حفظ الأسعار المنشورة يتم في قاعدة البيانات، لا على نظام ملفات Vercel المؤقت.
6. لا يتم نشر ملفات الاختبار أو الـ fixture الاصطناعي؛ `tests/fixtures/price-book.complete.TEST-ONLY.json` للاختبارات فقط.

## لوحة إدارة Beno

توجد لوحة الإدارة على `/admin` داخل نفس المشروع والنطاق. تتضمن تسجيل دخول بكلمة مرور، البحث وتصنيف البنود، تحرير أقل/متوسط/أعلى سعر والوحدة والمصدر والتاريخ والنقل والحالة، استيراد/تصدير JSON، إعدادات الهامش وطريقة التسعير وحد التغطية و68 تعريفًا مركزيًا لمعدلات الاستهلاك، مع مزامنة المعدلات المشتركة إلى مفاتيح التوافق القديمة التي تقرؤها المحركات المجمّدة، وتحرير نسب الهالك لكل مجموعة خامات بشكل مستقل. تبدأ المقايسة بنسخة مختصرة؛ يمكن فتح مكونات أي بند أو التحول إلى العرض التفصيلي. داخل التفاصيل يستطيع المهندس تعديل كمية أي سطر وإعادة الحساب أو إرجاع الكمية المحسوبة. تعديلات الكمية الخاصة بالمشروع تُحفظ حاليًا في تخزين المتصفح المحلي؛ أما الأسعار ومعدلات الموارد والهالك العامة فتُحرر من لوحة الإدارة. يمكنك حفظ مسودة ونشر إصدارات مع سجل تاريخي؛ لا تصبح الأسعار نافذة في حسابات الزوار إلا بعد النشر.

### تجهيز الدخول محليًا

```bash
npm run admin:setup
npm start
```

يحفظ الأمر كلمة المرور وسر الجلسة في `.env` (المستبعد من Git) ويطبع كلمة المرور مرة واحدة. افتح `http://127.0.0.1:4173/admin`. وضع التطوير يستخدم ملفًا محليًا داخل `.local/` للاختبار فقط.

### تجهيز لوحة الإدارة على Vercel

في Project Settings → Environment Variables أضف `BENO_ADMIN_PASSWORD` بطول 12 حرفًا على الأقل، و`BENO_ADMIN_SESSION_SECRET` بسر عشوائي لا يقل عن 32 حرفًا، بالإضافة إلى `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY`. طبّق ترحيل SQL أعلاه ثم أعد النشر وافتح `https://نطاق-الموقع/admin`. استخدم كلمة مرور مستقلة عن نسخة التطوير. مفاتيح Supabase لا تُرسل إلى المتصفح.

**قواعد النشر:** تستطيع حفظ أسعار ناقصة كمسودة، لكن النشر يُرفض إذا كانت تغطية أسعار البنود النشطة أقل من حد التغطية المحدد في إعدادات Beno. تغيير الحد إلى قيمة أقل قرار إداري صريح ولا يُنصح به من أجل إظهار رقم رئيسي غير مدعوم ببيانات كافية. البنود الجديدة تُضاف للكتالوج، لكنها لا تدخل في حصر الكميات تلقائيًا ما لم تكن مرتبطة بمنطق المحركات الأصلي.

## كيف تم تضمين Beno؟

في `index.html` يوجد وسم واحد:

```html
<script src="/beno-chat.js" defer data-api="/"
  data-brand="Beno" data-accent="#2864e8"
  data-whatsapp="201550130114" data-dir="rtl"
  data-position="right" data-theme="auto" data-autoopen="false" data-welcome="true"></script>
```

لا يلزم `data-api` لأن الويدجت يستخدم نفس أصل الصفحة (`/api/...`). إن تغيّر رقم WhatsApp عدّل `data-whatsapp`.

## بوابات قبل الإنتاج

- يحتوي الكتالوج التشغيلي v8 على 18 فجوة سعر، و37 سعرًا قديمًا أو بلا تاريخ حديث وفق حد 90 يومًا؛ أما 291 صفًا موسعًا من النشرة فمحفوظة خارج البحث النشط؛ يجب مراجعة المصادر محليًا قبل استخدام الأرقام في ميزانية تنفيذ.
- لا تُعرض قيمة إجمالية رئيسية عند بقاء فجوة سعر أو كمية مطلوبة؛ تغطية السعر الرقمي وحدها لا تكفي.
- لا تستخدم fixture الاختبار ككتالوج إنتاج.
- لم يُثبت النشر الحي على مشروع Vercel/Supabase الهدف ضمن هذه الحزمة.
- يجب التحقق من قاعدة البيانات وسياسة RLS ومعدل الطلبات الدائم بعد إضافة متغيرات البيئة.
- يجب إجراء اختبار قبول أخير على النطاق الإنتاجي، ويشمل إنشاء lead فعليًا والتحويل إلى WhatsApp.
- هذا إصدار Alpha وليس إعلان جاهزية للإنتاج أو مراجعة هندسية بشرية.
