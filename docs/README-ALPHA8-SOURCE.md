```bash
python -m http.server 8000
```




## الحدود التي لا يجوز تجاوزها تجاريًا

- لا يوجد Backend أو تسجيل دخول آمن أو قاعدة بيانات مشتركة؛ حفظ الجلسة وبيانات الإدارة على نفس المتصفح/الجهاز فقط.
- الهامش الشامل غير سري تقنيًا في المتصفح رغم عدم عرضه كنسبة/بند؛ انقل حساب الأسعار والهامش إلى الخادم قبل تسعير العملاء علنًا.
- لا تعتبر المعدلات المساحية حصرًا إنشائيًا معتمدًا. اعتماد الكميات يتطلب رسومات/مواصفات ومراجعة مهندس، وكل سعر يتطلب مصدرًا وتاريخًا وشروط توريد صالحة.
- لا تدّعي دقة ±10% أو اكتمال التكلفة مع وجود فجوات. زر طلب المراجعة لا ينشئ تذكرة مركزية قبل وجود backend.

## دورة حصر الموارد

1. حدّد مساحة كل دور وعدد الأدوار، مع خيار البدروم، ثم راجع جدول الحصر الذي يحتوي على مدخلات مستقلة لكل دور.
2. يمكن ترك الحديد والخرسانة فارغين ليستخدم المحرك المعدلات المساحية الاسترشادية، أو إدخال كمية يدوية لكل دور. إدخال كمية يدوية يتقدم على المعامل العام لذلك البند. لا يطبق المحرك معدل الحديد/الخرسانة أو مساحات التشطيب الافتراضية للدور العادي على البدروم تلقائيًا؛ يلزم إدخال حصر البدروم.
3. أدخل مساحات الحوائط نصف طوبة وطوبة كاملة، والمحارة والطرطشة، والسيراميك، والدهانات، والعزل، والجبس، ومساحات الفتحات والنقاط والخدمات حين تتوفر؛ لا تُستنتج من مساحة الدور وحدها.
4. عند اختيار **خلط الخرسانة بالموقع** يحسب المحرك الأسمنت والرمل والزلط والماء من حجم الخرسانة ومعدلات الخلطة. عند اختيار **الخرسانة الجاهزة** يظهر حجم الخرسانة وسعر توريدها إن وُجد، ولا يكرر مكونات الخلطة في قائمة الطلبيات.
5. المصنعية منفصلة قدر الإمكان عن التوريد وعن المعدات/المضخة. أي بند بلا سعر يبقى فجوة ولا يضاف إلى مبلغ مزعوم.
6. قائمة طلبيات الشراء تجمع الموارد من الأدوار المختلفة. إذا كان أحد الأدوار أو أحد البنود المساهمة غير محصور، قد تظهر كمية معلومة جزئيًا مع وسم أن إجمالي الطلبية غير مكتمل.
7. يمكن تصدير تفاصيل الحصر حسب الدور وقائمة طلبيات الشراء بصيغ CSV. يعرض المحرك شارة «مراجعة قبل الطلب» عند وجود معدل متعارض أو سعر وطني بديل أو نقل غير مؤكد أو سعر قديم. راجع وحدات المورد وعروض الأسعار قبل إرسال طلبية فعلية.

## معدلات الاستهلاك — تنبيهات مصدرية

المعدلات الافتراضية مأخوذة من ملف المعدلات الذي أرسله المستخدم، وهي معدلات تقديرية عملية وليست جدول كميات تصميميًا. المحرك يجعل التعارضات الظاهرة في المصدر مرئية ولا يخفيها:

- **حديد التسليح:** 60–100 كجم/م² متسق تقريبًا مع مثال 9–15 طنًا لمساحة 150 م²، لكنه يتعارض مع «طن لكل 80 م²» (12.5 كجم/م²). يستخدم الحصر الافتراضي نطاق 60–100 كجم/م² للتخطيط فقط، ويلزم اعتماد معدل الشركة أو الرجوع للرسومات.
- **أسمنت الهيكل:** يذكر المصدر 6–8 شكاير/م²، لكنه يذكر أيضًا 60–80 شيكارة لكل 100 م²؛ كما أن حساب 0.30–0.40 م³ خرسانة/م² × 7 شكاير/م³ يختلف عن 6–8 شكاير/م². لا يستخدم المحرك معدل 6–8 شكاير/م² في خلط الموقع؛ يحسب مكونات الخلطة من حجم الخرسانة.
- **أسمنت المحارة:** المصدر يذكر نطاقين 7.5–10 و9–12 كجم/م²؛ يعرض المحرك نطاقًا جامعًا 7.5–12 كجم/م²، ويظهر التنبيه.
- توزيع الهيكل بالمسطح على كل دور هو توزيع تخطيطي لا تفريد حديد أو خرسانة من الرسومات. الأساسات والبدروم والأعمدة والكمرات والأسقف تحتاج إلى حصر إنشائي مستقل.

راجع `BENO-RESOURCE-TAKEOFF-2026-10-19.md` لقائمة المعدلات الكاملة.

## الأسعار

تظل أسعار السوق الوطنية المسجلة بدائل وليست عروض أسعار أقصر. كل بند قد يحمل سعرًا ومصدرًا وتاريخًا وحالة توثيق وشرط نقل. البنود ذات الحالة «سعر غير مدخل» تظل بلا سعر حتى تضيف بياناتك من لوحة الإدارة. لا تضمن التغطية العددية للكتالوج اكتمال الحصر أو صلاحية طلبية شراء.

## حدود النسخة الحالية

- Front-end محلي فقط؛ التعديلات تحفظ في `LocalStorage` على نفس المتصفح والجهاز.
- لا يوجد تسجيل دخول آمن أو Backend أو قاعدة بيانات مشتركة أو سجل مراجعات مركزي في هذه الحزمة.
- الوكيل حتمي ومحدود الأنماط المدعومة، ولا يفهم كل صياغة عربية مثل الإنسان ولا يتعلم تلقائيًا.
- المعدلات الافتراضية تساعد في التخطيط الأولي فقط. طلب الشراء التنفيذي يجب أن يعتمد على حصر راجعه مهندس مختص، ومواصفة خامة محددة، وسعر مورد صالح زمنيًا وشامل النقل/المناولة حيث يلزم.
- لا تدّعي المنصة دقة ±10% قبل اختبارها على مقايسات ومشروعات منفذة ومعايرة قواعد الكميات والأسعار.

## قبل الإطلاق التجاري

1. توصيل واجهة آمنة بقاعدة بيانات مشتركة مع تسجيل دخول وصلاحيات وسجل تغييرات.
2. حفظ إصدارات من السعر والمعدل والمواصفة المستخدمة داخل كل مقايسة حتى يمكن إعادة إنتاجها.
3. إضافة عروض الأقصر المحلية، ومدة صلاحيتها، وشروط النقل والتحميل والتنزيل والضرائب والحد الأدنى للطلب.
4. تحديد نطاق كل باقة تشطيب واعتماده تجاريًا، خصوصًا «نصف تشطيب».
5. إدخال مقايسات حقيقية للتحقق من الخطأ حسب كل بند وباقة ونوع مبنى.
6. إضافة استيراد جداول حصر من الرسومات ومراجعة بشرية قبل اعتبار أي مقايسة طلبية تنفيذية.


## Security limitation — comprehensive margin

This is a browser-only alpha. The comprehensive margin is blended into displayed unit rates, but it is **not confidential**: a user can inspect JavaScript/localStorage and recover client-side values. The UI says this explicitly. Do not use this build for public commercial quoting where the margin must remain secret. Enforce the margin and construct customer quotes on a server API before production; admin authentication and shared persistence must also move server-side.


## v0.4.0-alpha.3 UI update

The public-facing experience now follows a 5-step customer journey. The result is separated into Summary, Phases, Materials, Full BOQ, and Assumptions/Sources tabs. It supports package comparison, item-level calculation details, print/save-as-PDF, browser share/clipboard fallback, WhatsApp share text, responsive stepper controls, and a local light/dark theme preference. The admin workspace remains separate from the public landing experience.

Important: this remains a local prototype. Browser-local admin entry is not authentication; the internal margin is not secret in client-side code; requests and pricing changes are not shared between devices. Deploy only after implementing server-side authentication, authorization, persistent database storage, and server-side price/margin calculation.
