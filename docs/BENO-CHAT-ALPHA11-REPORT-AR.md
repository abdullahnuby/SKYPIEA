# تقرير تطوير تجربة Beno — Alpha 11

**التاريخ:** 22 أكتوبر 2026  
**النطاق:** تحسين تجربة بداية المحادثة وهوية مساحة العمل، من دون تغيير محرك الحساب أو أسعار الكتالوج.

## ما تم تنفيذه

- إضافة معاينة هندسية منظمة داخل ترحيب Beno توضّح طريقة عرض ثلاثة أمثلة من بنود المقايسة: الحفر الشامل، والردم كتوريد ومصنعية، والدهانات كتوريد ومصنعية.
- وضع تنبيه مرئي بأن المعاينة توضيحية فقط ولا تحتوي أسعارًا أو كميات افتراضية؛ ليست نتيجة مقايسة تخص زائرًا فعليًا.
- تنظيم كل مثال في أعمدة توضح مجموعة العمل، وطريقة تنظيم البند، ونطاق ما يتم توضيحه للمهندس.
- إضافة بطاقة جانبية تشرح عناصر المراجعة: الكمية ووحدة القياس، والهالك وكمية التوريد، ومصدر السعر وتاريخ مراجعته.
- تحسين الهوية البصرية لمساحة المحادثة بخلفية تقنية خفيفة، وحالة مرئية في رأس Beno، ومسافات وخطوط أكثر اتساقًا.
- إبقاء عنوان الترحيب في أعلى المحادثة عند فتح مساحة العمل بدل تمرير الرسائل إلى أسفل تلقائيًا.
- تقصير نص خانة الكتابة ليلائم الهاتف، مع الحفاظ على دعم تعدد الأسطر وإبقاء خانة الكتابة ثابتة أسفل مساحة المحادثة.
- إصلاح تباين بطاقات البداية في الوضع الداكن، مع دعم إعداد الثيم الداكن الصريح وكذلك الثيم المتبع لإعداد الجهاز.
- إضافة أدوار وصول دلالية لجدول المعاينة وفحوص قبول تمنع تراجع التباين أو قص المعاينة على الكمبيوتر.

## ما لم يتغير

- لم تتغير محركات الحصر أو الحساب، ولم تتغير الأسعار النشطة أو معدلات الاستهلاك.
- لم يُضف نموذج لغوي أو API خارجي جديد. ما زال Beno يستخدم الحوار الحتمي وقواعد المعرفة ومحركات الحساب الحالية؛ تحسين الواجهة لا يعني تحسنًا تلقائيًا في قدرة الاستدلال اللغوي.
- لا تتحول الصفحة العامة إلى لوحة منصة أو تدفق أسئلة إجباري؛ يستطيع الزائر كتابة طلبه مباشرة أو اختيار واحدة من بدايات الاستخدام الثلاث.

## نتائج التحقق

- `npm test`: نجحت مجموعات اختبارات Node الـ18 كلها.
- `npm run build`: نجح تدقيق كتالوج الأسعار وتدقيق قاعدة معرفة الوكيل والبناء.
- `npm run test:workspace`: نجح على الكمبيوتر والهاتف في الوضعين الفاتح والداكن؛ 0 أخطاء متصفح، وتم التحقق من المعاينة التوضيحية، وغياب الأسعار المصطنعة، والتباين في الوضع الداكن، وملاءمة المعاينة لمساحة الكمبيوتر.
- `npm run test:browser`: نجح في أربعة تركيبات (هاتف/كمبيوتر، فاتح/داكن)، مع بقاء الإجمالي مخفيًا عند وجود فجوات، وإمكانية تعديل الكمية وإعادة حسابها.
- `npm run test:landing`: نجح على الهاتف والكمبيوتر، مع 16 دعوة للمحادثة ودون تمرير أفقي.
- `npm run test:admin:browser`: نجح؛ واجهة الإدارة مختبرة بمحول API وهمي، ومسار الخادم الحقيقي مغطى باختبارات Node.
- `npm run check:secrets` و`npm run audit:prices:all`: نجحا.

## القيود المعروفة

- هناك 18 فجوة سعر و37 سعرًا قديمًا أو غير مؤرخ في كتالوج التشغيل الحالي. يلزم تحديث ومراجعة الأسعار قبل اعتماد ميزانية تنفيذية.
- أرقام المعاينة ليست قياسًا أو تسعيرًا؛ إنها مثال بصري على تنظيم البند فقط، ولا تعرض أرقام كميات أو أسعار مختلقة.
- لم يتم النشر على Vercel ولم تُنفّذ ترحيلات إنتاجية على Supabase.
